# Gilded Rose C++17 Cursor Rules 보고서

## 1. 작성 목적

본 보고서는 Gilded Rose C++17 레거시 프로젝트에서 Cursor AI가 일관된 기준으로 QA, 테스트 작성, 리팩토링을 수행하도록 `.cursorrules` 파일에 정의한 프로젝트 규칙을 정리한 문서이다.

Gilded Rose는 레거시 코드의 기존 동작 보존이 중요한 카타 과제이므로, 기능 변경보다 테스트 기반의 안전한 리팩토링을 우선한다.

## 2. 프로젝트 기술 스택

- 언어 표준: C++17
- 빌드 시스템: CMake
- 테스트 프레임워크: Google Test
- 커버리지 도구: gcov, lcov

Cursor AI는 위 기술 스택을 기준으로 코드 작성, 테스트 작성, 빌드 및 검증 방법을 제안해야 한다.

## 3. 절대 준수 규칙

다음 규칙은 Gilded Rose 도메인에서 반드시 지켜야 하는 핵심 제약이다.

- `Item` 구조체는 수정하지 않는다.
- 기존 레거시 인터페이스의 공개 계약은 명시적 요청 없이는 변경하지 않는다.
- `quality` 값은 기본적으로 0 이상 50 이하를 유지해야 한다.
- 예외적으로 `Sulfuras`는 전설 아이템이므로 quality 80을 유지할 수 있다.
- `sellIn` 값은 음수가 될 수 있으므로 0으로 보정하지 않는다.
- 테스트나 요구사항이 명확히 정의하지 않은 동작 변경은 피한다.

이 규칙들은 리팩토링 중에도 변경되면 안 되는 도메인 불변 조건이다.

## 4. 테스트 작성 규칙

리팩토링 전에 테스트를 먼저 추가하거나 보완해야 한다. 테스트는 Google Test를 사용하며, fixture가 필요한 경우 `TEST_F`를 사용한다.

테스트는 Given-When-Then 구조가 드러나도록 작성한다.

- Given: 테스트 대상 아이템과 초기 상태를 준비한다.
- When: `updateQuality()` 등 대상 동작을 실행한다.
- Then: `quality`, `sellIn` 등 기대 결과를 검증한다.

반드시 포함해야 하는 경계값은 다음과 같다.

- `quality == 0`
- `quality == 50`
- `sellIn == 0`
- `sellIn == -1`

테스트 대상 아이템은 일반 아이템뿐 아니라 다음 특수 아이템을 포함해야 한다.

- `Aged Brie`
- `Backstage passes`
- `Sulfuras`
- 현재 요구사항에서 지원하는 경우 `Conjured` 아이템

각 테스트는 하나의 동작을 명확히 설명하도록 작고 집중된 형태로 작성하는 것을 권장한다.

## 5. 리팩토링 규칙

리팩토링은 테스트가 Green 상태일 때만 진행한다. 의미 있는 변경을 한 뒤에는 관련 테스트를 다시 실행하여 기존 동작이 유지되는지 확인한다.

리팩토링 시 다음 기준을 따른다.

- 동작 변경 없이 구조 개선을 우선한다.
- 작고 되돌리기 쉬운 단위로 변경한다.
- 매직 넘버는 의미 있는 상수로 분리하는 것을 권장한다.
- 테스트가 부족한 상태에서 광범위한 재작성은 피한다.
- 불필요한 추상화보다 단순한 C++17 코드를 우선한다.
- 명시적 승인 없이 새 의존성을 추가하지 않는다.

## 6. 코드 스타일 지침

코드는 레거시 유지보수자가 쉽게 읽고 검토할 수 있어야 한다.

- 아이템 종류, quality 제한, sellIn 임계값은 의미 있는 이름으로 표현한다.
- 동일한 비즈니스 규칙을 여러 위치에 중복 구현하지 않는다.
- 주석은 명확하지 않은 비즈니스 규칙을 설명할 때만 사용한다.

## 7. 적용 결과

프로젝트 루트에 `.cursorrules` 파일을 생성하여 Cursor AI가 다음 기준을 항상 참고하도록 구성하였다.

- Gilded Rose 도메인 불변 조건 유지
- 테스트 우선 리팩토링
- Google Test 기반 경계값 테스트 강화
- C++17, CMake, gcov/lcov 기반 개발 흐름 준수
- 레거시 코드의 동작 보존과 점진적 개선

## 8. 결론

작성된 `.cursorrules`는 Gilded Rose C++17 프로젝트에서 Cursor AI가 레거시 코드의 핵심 제약을 침해하지 않고, 테스트를 기반으로 안전하게 리팩토링하도록 돕는 프로젝트 전용 작업 규칙이다.
